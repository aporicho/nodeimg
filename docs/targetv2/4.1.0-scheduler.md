# 调度器 Facade

> 薄 facade,接收外部执行请求,委派 Planner 产出计划,交给 Runtime 执行。

---

## 文档状态

`impl` —— 作为 Planner(`4.1.1`)与 Runtime(`4.1.2`)的入口封装,接口已收敛。

---

## 实例数量与生存期(targetv2 首版)

**Scheduler facade 是 Session 级实例(首版):**

- 每个 Session 持有一个 Scheduler facade 实例
- Scheduler facade 的生存期与 Session 绑定——Session 关闭时销毁
- **CLI / Server 模式下**:CLI 进程启动一个"无 Session"的 Scheduler facade 实例,生存期与 CLI 进程相同

**不是引擎级单例:**

- 不同 Session 有不同的 Graph,需要独立的 DirtyState
- 切换 Project 时 Scheduler 随着 Session 销毁,不需要手动 clear
- 多 Session 场景(未来)下,多个 Scheduler facade 共享同一个 Runtime(Runtime 是进程级唯一)

**首版说明:**

- 首版支持单 Session,所以**实际只有一个 Scheduler facade 实例**
- 但文档明文"Session 级实例"是为了保证未来多 Session 扩展**不需要改核心**

## 层归属

**跨 Layer 2 + Layer 4 的薄 facade**。职责:

- 接收外部请求
- 协调 Planner + Runtime 的调用顺序
- 对外保持 target 时代 Scheduler 的接口形态,降低迁移成本
- **持有 `DirtyState` 的生命周期**——Planner 是纯函数不能持有状态,Runtime 不关心脏状态,所以 Scheduler facade 是唯一的合理持有者
- **协调缓存失效**——在图变更时直接调 CacheManager 的 `invalidate_subgraph`,不经 Runtime(Runtime 只管执行,不管失效)

**所有权清单:**

- 本模块拥有:
  - `DirtyState`(接受 Planner 的纯函数推导结果)
  - `DirtyState` 的生命周期(创建 / 更新 / 清除)
  - Plan memoization cache(可选,作为性能优化)
- 本模块引用但不拥有: `Graph`(GraphController)、`NodeDef`(NodeManager)、`Runtime`(Layer 4)
- 本模块**不**拥有: `single-flight` 守卫、正式 cache、执行状态、节点定义

## 与 target 时代 Scheduler 的关系

target 时代的 Scheduler 是一个**大 Scheduler**——同时负责:

- 脏状态维护
- 执行计划生成
- 缓存协调
- 执行器分发
- 取消、进度、状态机

targetv2 把这些职责**拆开**:

| 原 Scheduler 职责 | targetv2 归属 |
|-----------------|------------|
| **脏状态持有** | **Scheduler facade**(既非 Planner 也非 Runtime) |
| 脏状态推导算法 | Planner(Layer 2,纯函数) |
| 执行计划生成 | Planner(Layer 2) |
| `ExecSignature` 构造 | Planner(Layer 2) |
| CookingContext 枚举 | Planner(Layer 2) |
| **缓存失效协调** | **Scheduler facade**(直接调 CacheManager) |
| 缓存查询 | Runtime(Layer 4) |
| 执行器分发 | Runtime(Layer 4,经 CapabilityRegistry) |
| `single-flight` 守卫 | Runtime(Layer 4) |
| 产物回源 / 写入 | Runtime(Layer 4) |
| 取消、进度、状态机 | Runtime(Layer 4) |

**Scheduler facade 自身负责:**

- 接受外部 `set_mode` / `request_execution` / `cancel_execution` / `query_state` 接口
- 接受 `notify_graph_changed` 事件并通过 Planner 的纯函数推导出新 DirtyState
- 在图变更时直接调 CacheManager 的 `invalidate_subgraph`
- 把 `request_execution` 翻译成 Planner + Runtime 的组合调用
- 对外暴露稳定接口,内部实现可以演化

**为什么 Scheduler facade 持有 DirtyState:**

- Planner 是纯函数,不能持有可变状态
- Runtime 专注执行,不关心"下次该跑什么"
- Scheduler facade 是自然的"规划侧状态容器"

## 对外接口

与 target 时代相同的最小接口集:

```rust
trait Scheduler {
    fn set_mode(&self, mode: ExecutionMode);
    fn notify_graph_changed(&self, event: GraphChangedEvent);
    fn notify_graph_replaced(&self, snapshot_meta: SnapshotMeta);
    fn notify_artifact_selected(&self, selection: ArtifactSelection);
    fn request_execution(&self, request: ExecutionRequest) -> ExecutionTicket;
    fn cancel_execution(&self, run_id: RunId) -> Result<(), EngineError>;
    fn query_state(&self) -> SchedulerStateSummary;
}
```

**接口变更(相对 target):**

- `request_execution` 的 `ExecutionRequest` 新增 `fidelity: EvaluationFidelity` 字段(见 `0.1.1-execution-models.md` §1.1)
- `notify_graph_changed` 的事件语义不变
- `query_state` 返回值中的 `runtime_state` 可能包含 `fidelity` 信息

## 内部调度流程

### 流程 1: request_execution

```
┌──────────────────────────────────────────────────────────┐
│ 1. 接收 request_execution(ExecutionRequest)               │
│                                                          │
│ 2. 读当前 Graph snapshot(通过 GraphController)            │
│                                                          │
│ 3. 读 self.dirty_state(Scheduler facade 持有)            │
│                                                          │
│ 4. 调用 Planner::plan(                                    │
│       graph, cooking_context, &self.dirty_state,         │
│       node_defs, selections)                             │
│    → ExecutionPlan (纯函数输出,不含 run_id/generation)   │
│                                                          │
│ 5. 调用 Runtime::try_start_run(plan, mode)               │
│    → Arc<RunHandle> (Runtime 注入 run_id/generation)     │
│                                                          │
│ 6. 返回 ExecutionTicket { run_id, handle_ref }           │
└──────────────────────────────────────────────────────────┘
```

### 流程 2: notify_graph_changed

```
┌──────────────────────────────────────────────────────────┐
│ 1. 接收 GraphChangedEvent                                 │
│                                                          │
│ 2. 读当前 Graph snapshot                                  │
│                                                          │
│ 3. 调用 Planner::propagate_dirty(                         │
│       &event, &graph, &self.dirty_state)                 │
│    → new_dirty_state (纯函数输出)                         │
│                                                          │
│ 4. self.dirty_state = new_dirty_state                    │
│                                                          │
│ 5. 直接调 CacheManager::invalidate_subgraph(              │
│       affected_nodes)                                    │
│    (不经 Runtime——Runtime 只管执行)                       │
│                                                          │
│ 6. 可选: publish(DirtyStateChanged) 事件                  │
└──────────────────────────────────────────────────────────┘
```

### 流程 3: Runtime 执行完成后的清理

```
Runtime 的 RunFinishedEvent 到达 Scheduler facade:
    → self.dirty_state.clear_completed(&run_result)
    → 已成功执行的节点从 dirty_nodes 移除
```

**关键:** Scheduler facade 不持有 `single-flight` 守卫——那是 Runtime 的职责。所以 `request_execution` 可能返回 `Err(RunInFlight)`,来自 Runtime 的 `try_start_run()`。

## 依赖接口

- `GraphController::get_graph_snapshot()` —— 读当前 Graph
- `Planner::plan(graph, ctx, dirty, node_defs, selections)` —— 规划(纯函数)
- `Planner::propagate_dirty(event, graph, current)` —— 推导新 DirtyState(纯函数)
- `Planner::propagate_artifact_selection_change(node_id, graph, current)` —— artifact 选用变更脏传播
- `NodeManager` 实现的 `NodeDefQuery` trait —— 给 Planner 传的 NodeDef 查询源
- `ArtifactManager` 实现的 `ArtifactSelectionQuery` trait —— 给 Planner 传的 Impure 节点选用查询源(签名依据)
- `Runtime::try_start_run(plan, mode)` —— 启动执行(mode = `ExecutionMode::OneShot { fidelity }` 或 `Continuous`)
- `Runtime::cancel(run_id)` —— 取消
- `Runtime::get_state()` —— 查询
- **`CacheManager::invalidate_subgraph(node_ids)`** —— 图变更时直接失效(不经 Runtime)
- `EventSystem::publish(event)` —— 广播
