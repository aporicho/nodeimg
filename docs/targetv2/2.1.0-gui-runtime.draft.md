# GUI Runtime

> GUI runtime 的新架构边界草案。旧 `docs/target/` 保留为历史资料；`docs/targetv2/` 用于沉淀新的 GUI 架构基线。

## 目标

GUI runtime 的目标是保持一棵统一控件树，同时把普通控件、运行时系统、资源管理、事件分发和渲染管线分开：

```text
App
  业务状态、构建 Desc、处理 GuiEvent / PlatformEffect

Context
  GUI runtime facade，协调 update / render / handle_event

RuntimeSystems
  popup、dropdown、text input、overlay、IME 等跨帧行为

Tree
  reconcile 后的节点实例、布局 rect、children、scroll offset

Widget
  Props + build()，声明控件结构和 anatomy parts

Renderer
  DrawCommand -> GPU，不知道业务和 widget props
```

## 边界规则

- Props 只放外部声明数据：label、value、disabled、options、content。
- hover、pressed、focus、caret、selection、preedit、overlay open state 等临时状态属于 interaction state 或 runtime systems。
- 普通控件不得依赖 `Context`、tree internals、renderer internals、`wgpu`、shell API 或 app 代码。
- 普通控件新增时，不应修改 `Context`、`event::router`、`tree::layout`、`tree::paint`、`renderer`、`shell`。
- 如果新增控件必须修改这些核心模块，说明它在增加框架能力，必须单独设计。

## RuntimeSystems

`RuntimeSystems` 是 `Context` 内部的运行时系统聚合层。它先用具体类型聚合，不引入动态插件系统：

```rust
pub(crate) struct RuntimeSystems {
    popup: PopupSystem,
    dropdown: DropdownSystem,
    text_input: TextInputSystem,
}
```

目标 API：

```rust
impl RuntimeSystems {
    pub(crate) fn compose_desc(&mut self, tree: &Tree, desc: Desc, root_rect: Rect) -> Desc;
    pub(crate) fn sync_with_tree(&mut self, cx: RuntimeSyncCx<'_>);
    pub(crate) fn handle_pre_gesture_event(
        &mut self,
        cx: RuntimeEventCx<'_>,
        event: &AppEvent,
    ) -> RuntimeEventResult;

    pub(crate) fn open_overlay(&mut self, tree: &Tree, request: OverlayRequest);
    pub(crate) fn close_overlay(&mut self, tree: &Tree, interaction: &mut InteractionState);
    pub(crate) fn overlay_open(&self) -> bool;
    pub(crate) fn ime_request(&self, tree: &Tree, focused: Option<NodeId>) -> ImeRequest;
    pub(crate) fn paste_focused_text(
        &mut self,
        tree: &Tree,
        focused: Option<NodeId>,
        text: &str,
    ) -> FrameworkOutput;
}
```

事件顺序固定为：

```text
interaction
scroll
runtime pre-gesture
  popup
  dropdown
  text_input
gesture
```

如果 runtime pre-gesture 阶段消费事件或产出事件/effect，必须取消当前 gesture session。

## ResourceRegistry

GPU 资源不直接散落在 `Context` 字段里，而由 resource registry 管理：

```rust
pub(crate) struct ResourceRegistry {
    textures: HashMap<TextureHandle, Arc<wgpu::TextureView>>,
}
```

短期保留 texture map 访问给 paint 使用；长期可以抽象成 texture resolver，避免 paint 直接知道具体 registry 存储。

## Widget Anatomy

控件内部节点使用 `root::part` 命名：

```text
button
button::label

slider
slider::label
slider::track
slider::thumb

text_input
text_input::label
text_input::field
text_input::value
```

规则：

- `root::part` 是框架 anatomy，不是业务 API。
- 业务事件默认上报 owner/root id。
- 新框架控件 root id 应避免包含 `::`。
- 现有应用 id 如果包含 `::`，TargetResolver 通过最长 widget 前缀匹配继续兼容。

## 当前不做

- 不引入 `Box<dyn GuiSystem>` 插件系统。
- 不泛型化 `WidgetProps<Message>`。
- 不改 `App` trait。
- 不拆 `BoxStyle`。
- 不改 renderer pipeline。

这些方向需要在后续 targetv2 文档中单独设计。
