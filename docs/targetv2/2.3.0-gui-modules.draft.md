# GUI Modules

> targetv2 GUI 文件结构与模块边界。本文档只定义 `gui/src/` 的目标结构、目录职责、依赖规则和迁移路径；GUI Tree 的状态模型归 `2.2.0-gui-tree.draft.md`。

## 目标

- 文件结构直接反映软件结构。
- `mod.rs` 只做导出与模块组织，不承载核心业务逻辑。
- 不使用 `utils.rs` / `helpers.rs` 作为长期文件名。
- 目录按职责切分，而不是按当前 demo 页面切分。
- 通用 GUI crate 不持有图片 demo 的业务 glue。

## 目录职责

- `context.rs`：GUI 对外门面，协调 update、reconcile、layout、event、runtime GC、render。
- `output.rs`：`GuiOutput`、`GuiEvent`、`PlatformEffect` 等对外输出模型。
- `tree/`：GUI Tree 的 arena、节点、Desc、props、runtime slots、reconcile、layout、hit、paint。
- `action/`：`ActionId`、`GuiAction`、action payload 和 dispatch。它是 GUI 到 App 的唯一语义出口。
- `event/`：输入事件模型、路由、target resolve、gesture adapter。
- `gesture/`：tap、double click、drag、resize、long press 等识别。
- `interaction/`：`RootInteractionRuntime` 的 reducer 与查询。长期状态挂在 Tree root runtime，不在本目录另建状态仓库。
- `widget/`：通用控件 props、anatomy、atoms、frameworks、painters、文本编辑算法。
- `canvas/`：节点画布的 props、runtime slots、Desc builder、reducer、camera、node card、port、connection。
- `panel/`：面板声明、props、runtime slots、builder、reducer、内置 panel instances。
- `overlay/`：node palette、context menu、tooltip、modal 的 runtime、placement、dismiss、builder。
- `resource/`：GUI 资源 id、状态、registry、resolver。实际 GPU 对象不在 Tree 内。
- `persistence/`：`ProjectLayout` import / export，只处理可持久化 UI layout 字段。
- `accessibility/`：从 GUI Tree 派生 accessibility tree，不另存 UI 状态。
- `renderer/`：DrawCommand、GPU pipeline、text measurer、renderer facade。
- `shell/`：窗口、surface、GPU 初始化、平台事件翻译、cursor、IME、runner。
- `theme/`：设计 token、dark/light theme。

## 依赖规则

禁止依赖：

```text
tree -> engine
tree -> shell
tree -> wgpu
tree -> app
widget -> engine
widget -> shell
widget -> wgpu
widget -> app
renderer -> engine
renderer -> app
engine -> gui
```

允许依赖：

```text
app -> gui
app -> engine
context -> tree / widget / layout / event / resource / renderer API
canvas -> tree / action types
panel -> tree / action types
overlay -> tree / action types
shell -> context / renderer
```

## Public API 约束

`gui/src/lib.rs` 只暴露稳定使用面：

```rust
pub mod context;
pub mod output;
pub mod tree;
pub mod widget;
pub mod canvas;
pub mod panel;
pub mod overlay;
pub mod action;
pub mod renderer;
pub mod shell;
pub mod theme;

pub(crate) mod event;
pub(crate) mod gesture;
pub(crate) mod interaction;
pub(crate) mod resource;
pub(crate) mod persistence;
pub(crate) mod accessibility;
```

公共 API 应集中在：

- `Context` / `GuiContext`
- `Desc`
- `NodeProps`
- `ActionId`
- `GuiAction`
- `GuiOutput`
- `Theme`
- renderer / shell runner 的必要入口

## 当前结构到目标结构的迁移表

| 当前 | 目标 | 说明 |
| --- | --- | --- |
| `gui/src/tree/diff.rs` | `tree/reconcile.rs` | 命名改成实际职责。 |
| `gui/src/tree/runtime.rs` | `tree/runtime_slots.rs` + `tree/runtime_policy.rs` | 已迁移；旧 `tree/runtime.rs` 删除。 |
| `gui/src/panel/state.rs` | `panel/config.rs` + `panel/runtime.rs` + `panel/reducer.rs` | 已拆分；panel 状态已挂到 Tree runtime slots。 |
| `gui/src/panel/event.rs` | `panel/actions.rs` + `panel/reducer.rs` | action 模型和状态变更分开。 |
| `gui/src/canvas/popup.rs` | `overlay/node_palette.rs` 或 `overlay/context_menu.rs` | popup 属于 overlay 系统。 |
| `gui/src/runtime/resources.rs` | `resource/registry.rs` | resource registry 是 GUI service。 |
| `gui/src/runtime/systems.rs` | `overlay/`、`widget/`、`interaction/` | 不长期保留大杂烩。 |
| `gui/src/widget/systems/popup.rs` | `overlay/` | 已迁移；overlay 统一管理。 |
| `gui/src/widget/systems/dropdown.rs` | `overlay/` + `widget/atoms/dropdown.rs` + `widget/state/dropdown.rs` | dropdown UI、overlay 承载和打开状态已分离。 |
| `gui/src/widget/state/text_input.rs` | `widget/text_edit.rs` + `TextInputRuntime` | 算法 helper 保留，状态进 Tree。 |
| `gui/src/output.rs` | `output.rs` + `action/` | output 保留，语义 action 独立。 |

## 最小落地顺序

1. 新增 `action/`，建立 `ActionId -> GuiAction` 出口。
2. 重构 `tree/`，补 `NodeProps`、`RuntimeSlots`、`RuntimePolicy`、`OwnerLiveness`。
3. 新增 `overlay/`，把空白画布双击打开 node palette 迁到正式 overlay 路径。
4. 迁移 `panel` runtime 到 `panel_root` / `panel::<id>` runtime slots。
5. 迁移 text input 的长期状态到 Tree runtime slots。
6. 拆出 `resource/` 和 `persistence/`。

## App 侧结构

图片 demo 的业务 glue 不进入通用 GUI crate。App 侧建议形成：

```text
app/src/workspace/
├── mod.rs
├── view.rs
├── controller.rs
├── engine_adapter.rs
├── node_palette.rs
└── project_layout.rs
```

当前已落地：

- `view.rs`：workspace canvas / panel root 组合视图。
- `node_palette.rs`：node defs -> node palette overlay desc。

- `view.rs`：Engine graph + GUI tree runtime -> `Desc`。
- `controller.rs`：`GuiAction` -> `EngineFacade` / `Session`。
- `engine_adapter.rs`：`EngineFacade` -> GUI-friendly snapshot。
- `node_palette.rs`：node defs -> node palette desc / action payload。
- `project_layout.rs`：load / save project UI layout。

## 验证清单

- 每个目录是否有单一职责？
- 是否没有 `utils.rs` / `helpers.rs`？
- `mod.rs` 是否只做导出？
- Tree / Widget 是否不依赖 Engine、Shell、wgpu、App？
- App 是否是 GUI 和 Engine 之间唯一 glue？
- 长期 UI 状态是否最终都能归属到 GUI Tree？
