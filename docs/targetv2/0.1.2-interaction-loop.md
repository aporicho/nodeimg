## §2 五条结构义务

真源 ⑧ 在派生层的完整展开,共五条。**每一条都必须能在 PR review 时肉眼判断遵守与否**。

### §2.1 增量失效默认开启

**规则:**

- Planner(Layer 2)在参数 / 连线变化时只重算受影响子图
- "全量重算" **不作为默认模式存在**
- 任何"清空所有脏标记 → 触发全图执行"的代码路径都必须先改本文档

**判定方法(PR review):**

- 搜索 `invalidate_all` / `mark_all_dirty` / `reset_dirty` 类调用
- 任何新增此类调用的 PR 必须披露原因

**例外:**

- `clear_cache` / `replace_graph` 会触发 `generation` 推进,进而导致下一轮执行时缓存全部失效——这是受控的、由真源 ⑥ 允许的路径,不违反本规则
- 这两个操作本身**不**强制立即重算,只是让下次执行的脏判定失效

**权威定义:** `4.1.1-planner.md`

---

### §2.2 preview / full 分路

**规则:** `ExecutionRequest` 必须携带 `fidelity: EvaluationFidelity` 字段:

```rust
enum EvaluationFidelity {
    Preview {
        max_side: Option<u32>,      // 可选分辨率上限(长边像素)
        precision: PreviewPrecision, // 可选精度降级
    },
    Full,
}

enum PreviewPrecision {
    Float32,   // 无降级
    Float16,   // 半精度
    Int8,      // 首版不开,占位
}
```

**执行器的行为契约:**

- 执行器**可以**在 `Preview` 模式下:
  - 按 `max_side` 降分辨率
  - 按 `precision` 降精度
  - 跳过可选的后处理步骤
  - 跳过 artifact 写入
- 执行器**必须**在 `Full` 模式下按完整精度执行
- 首版允许执行器**忽略** `Preview` 的降级提示(行为等同 `Full`),但不允许在 `Full` 下偷降级

**路径分隔:**

- preview cache 归 Session(Layer 5),正式 cache 归 Runtime(Layer 4)
- preview 路径不得写入 artifact
- preview 路径不得触发 `Impure` 节点的 artifact 登记
- preview 路径**可以**读取正式 cache 作为 fallback(如果精度足够)

**判定方法(PR review):**

- 任何新的 `ExecutionRequest` 构造点必须显式指定 `fidelity`
- 默认不允许省略

**权威定义:** `0.1.1-execution-models.md` §1.1;`4.11.2-executor-contract.md`

---

### §2.3 交互路径优先

**规则:** 当 preview 执行与 full 执行竞争资源时, **preview 优先**。

**首版实现粒度:**

- Runtime 的 `single-flight` 守卫:如果当前是 `Full` 运行,收到 `Preview` 请求时 **取消当前 Full 运行,优先调度 Preview**
- 反向不成立: Full 请求不抢占 Preview

**首版默认策略:**

- `Preview` 请求收到后在 Runtime 中**立即调度**
- `Full` 请求收到后走 `single-flight` 正常排队

**不是目标:**

- 首版**不**实现细粒度抢占(节点中途打断)
- 首版**不**实现 preview / full 并行
- 首版**不**实现多级 preview(不同精度并列)

**判定方法(PR review):**

- Runtime 的调度决策代码必须显式分支 preview / full
- 任何引入"full 可以抢 preview"的变更必须先改本文档

**权威定义:** `4.1.2-runtime.md`

---

### §2.4 PR 披露义务

**规则:** 涉及真源 ①②④⑤⑥ 的 PR 必须在描述中包含 "对交互回路的影响" 字段,取值:

| 取值 | 含义 |
|------|------|
| `无影响` | 不触及 Planner 增量失效、Runtime preview/full 分路、Session preview 热路径、事件传播节流 |
| `改善` | 缩短了某条交互路径,附具体说明 |
| `风险` | 可能延长某条交互路径,附缓解措施 |

**留白的 PR 不得合并。**

**判定方法(PR review):**

- Reviewer 第一步检查 PR 描述是否包含该字段
- 如果缺失,要求 PR 作者补齐,不直接 review 代码

**权威定义:** `architecture-invariants.md` §4.4

---

### §2.5 Session 不独占 single-flight

**规则:**

- `single-flight` 全局守卫由 **Runtime (Layer 4)** 持有
- Session 只持有当前 `RunHandle` 的**引用**,不持有**权限**
- CLI / Server 不经过 Session,同样受 `single-flight` 约束

**原因:**

- 如果 `single-flight` 归 Session,CLI / Server 就没有这条不变量
- 两条路径就变成 "GUI 受约束,CLI 不受" 的不对称——等于两条不变量
- 静默踩坑的典型

**判定方法(PR review):**

- Session 代码不得直接变更 `RunHandle` 或 `single-flight` 状态
- 任何启动执行的调用都必须走 `Runtime::try_start_run()`
- Session 可以 `RunHandle::cancel()` 来请求取消,但这本身是 Runtime 提供的 API

**权威定义:** `architecture-invariants.md` §2 真源 ① / ⑥;`4.1.2-runtime.md`;`4.12.0-session.md`

## §3 派生字段

### §3.1 EvaluationFidelity

位于 `0.1.1-execution-models.md`,首版结构定义见 §2.2。

### §3.2 InteractionEvent

Session 产生的交互意图事件,只在 Session 内部流通,**不进** `EngineEvent`:

```rust
enum InteractionEvent {
    ParamChanged { node_id: NodeId, param: String },
    ConnectionChanged,
    NodeAdded { node_id: NodeId },
    NodeRemoved { node_id: NodeId },
    ArtifactSelected { node_id: NodeId, artifact_id: ArtifactId },
    ExportRequested { target: ExecuteTarget },
}
```

Session 的职责是把这些交互意图翻译成 `ExecutionRequest`,决定 `fidelity` 字段。

### §3.3 PreviewCacheEntry

Session 管理的 preview 缓存条目:

```rust
struct PreviewCacheEntry {
    key: PreviewCacheKey,
    value: Value,
    fidelity: EvaluationFidelity,
    last_accessed: Instant,
}

struct PreviewCacheKey {
    node_id: NodeId,
    output_pin: String,
    exec_signature: ExecSignature,
    fidelity_class: FidelityClass,
}

enum FidelityClass {
    Preview512,
    Preview1024,
    Preview2048,
    Full,
}
```

**关键约束:** `PreviewCacheKey` 与 `CacheKey` 不共享存储,它们是两个独立的 LRU 实例。

## §4 首版落地清单

**必须实现:**

1. `ExecutionRequest.fidelity: EvaluationFidelity` 字段(即使首版两种模式行为一致)
2. Runtime 的 single-flight 全局守卫
3. Session 模块的 preview cache 骨架(即使首版只是一个 `HashMap` 包装)
4. PR 模板补充 "对交互回路的影响" 字段

**允许推迟到后续版本:**

- 实际的 preview 降分辨率 / 降精度逻辑
- preview 抢占 full 的调度策略
- preview cache 的 LRU 淘汰逻辑
- 节点中途打断
- 细粒度增量失效(首版可以走"整个 Planner 重跑")

**不允许省略的原因:**

- 字段和分层一旦省略,未来加入就是破坏性变更——`ExecutionRequest` 形状变 = 所有执行器接口变 = 执行器签名变 = 缓存失效
- 字段和分层存在但实现为空,未来加入就是"填槽",零破坏性

## §5 数字预算(非规范性)

本节记录**参考预算**,不是规范性约束。具体测量由 benchmark 文档持续更新。

| 场景 | 参考预算 | 备注 |
|------|---------|------|
| 2K 图像、5 层线性图,参数变更到 preview 刷新 | `< 200ms` | 首版目标,未验证 |
| 同上,preview cache 命中 | `< 50ms` | 首版目标 |
| 全图 full 求值(无缓存) | 取决于执行器 | 不设通用预算 |
| undo / redo 响应 | `< 100ms` | 纯 Graph 操作,不触发执行 |

**以上数字不是真源的一部分,调整它们不需要改本文档。**

## §6 典型反模式清单

以下做法在 PR 中**禁止出现**,违反任何一条都需要先改本文档:

1. 任何执行路径的默认模式是"全图重算"
2. 任何 `ExecutionRequest` 构造省略 `fidelity` 字段
3. Session 代码中直接变更 `RunHandle` 或 `single-flight` 状态
4. preview cache 与正式 cache 合并存储
5. preview 路径写入 artifact
6. 任何涉及真源 ①②④⑤⑥ 的 PR 描述中缺失 "对交互回路的影响" 字段
7. 在 `Full` 模式下偷偷降分辨率或精度
