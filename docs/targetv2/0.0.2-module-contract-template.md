# 模块 contract 模板

> 用于约束 targetv2 文档中各引擎模块的统一写法,确保职责、提供接口、依赖接口、共享模型和验证方式完整闭合。

---

## 上位约束

本模板受 [`architecture-invariants.md`](architecture-invariants.md) 的 **8 条真源**管辖。任何模块设计若与真源冲突,必须先修改真源层文档,不得在本模板或具体模块文档中单方面绕过。

本文档末尾的「**全局设计约束**」是真源 ①(责任边界)和真源 ②(抽象模式)的具体落地项,不是独立决议——它们的权威解释始终在 `architecture-invariants.md`。若未来两份文档出现不一致,以 `architecture-invariants.md` 为准。

本模板同时受 [`first-principles-architecture.md`](first-principles-architecture.md) 的 **8 层分层** 管辖。每个模块文档必须显式说明自己属于哪一层。

---

## 适用范围

本模板适用于引擎内部模块文档,例如:

- 节点图控制器(Layer 1)
- Planner(Layer 2)
- CapabilityRegistry(Layer 3)
- Runtime(Layer 4)
- Session(Layer 5)
- 节点管理器(跨层服务)
- 缓存管理器(Layer 4)
- 产物管理器(Layer 4)
- 项目管理器(Layer 6)
- 事件系统(Layer 4 发出,Layer 5 订阅)
- 各类执行器与注册表

## 建议章节顺序

### 1. 文档状态

- `draft`: 方向已提出,但接口和边界仍可能变动
- `impl`: 职责、接口、共享模型、跨模块契约已收敛,可直接作为实现依据

### 2. 层归属(targetv2 新增)

必须显式声明本模块归属哪一层(Layer 0 ~ 7),以及它的**所有权清单**:

- 本模块拥有哪些状态?
- 本模块引用但不拥有哪些状态?
- 本模块的上游(我依赖谁)和下游(谁依赖我)?

### 3. 定义

说明模块是什么、解决什么问题,并明确一句话定义。

### 4. 职责边界

至少包含两部分:

- **属于本模块**
- **不属于本模块**

### 5. 提供接口

必须给出:最小接口集、输入/输出、状态修改、事件、副作用。

### 6. 依赖接口

必须列出本模块依赖外部模块的最小方法集,而不是只写"依赖某某模块"。

### 7. 共享模型

列出本模块直接使用的共享模型,并标明权威定义位置:

- 类型与节点 → `0.1.0-models.md`
- 执行模型 → `0.1.1-execution-models.md`
- 交互回路 → `0.1.2-interaction-loop.md`
- CookingContext → `0.1.3-cooking-context.md`
- Capability → `0.1.4-capability.md`
- Materialization → `0.1.5-value-materialization.md`

### 8. 错误与事件

说明模块公共错误类型,以及发布/订阅哪些事件。

### 9. 状态与生命周期

若模块持有长期状态,必须定义空闲、运行中、重置、加载、关闭语义。

### 10. 交互回路披露(targetv2 新增)

本模块对"参数变更 → 预览刷新"路径的影响:

- 本模块在该路径上的位置
- 本模块的任何操作是否会延长该路径
- 本模块如何支持 `preview` / `full` 分路

### 11. 关键流程

流程图可以保留,但必须建立在接口已经定义的前提上。

### 12. 验证清单

每篇模块文档末尾至少回答:

1. 每条外部箭头是否都有方法名?
2. 是否同时定义了提供接口和依赖接口?
3. 是否引用了唯一权威共享模型?
4. 是否说明了错误、事件、副作用?
5. 是否声明了层归属与所有权清单?
6. 是否披露了对交互回路的影响?
7. 是否与 `0.0.1-engine-contract.md`、`0.1.0-models.md`、`0.1.1-execution-models.md` 一致?

## 全局设计约束

以下决议在各模块文档中默认成立:

1. **布局不属于引擎**
2. **执行器统一接口**: 所有执行器实现同一 `Executor` trait
3. **运行时统一写产物**: 执行器无落盘权限,Runtime 根据 ArtifactPolicy 决定是否落产物
4. **Planner 驱动增量失效**: 脏状态 / 执行计划归 Planner(纯函数)
5. **Runtime 驱动缓存读写与回源**: single-flight 全局守卫归 Runtime
6. **事件统一 `publish(event)`**
7. **Provider 启动时静态注册**,不支持运行时热插拔
8. **NodeDef 是唯一权威节点模型**
9. **NodeDef = 瘦核心 + 默认化 ExecutionPolicy**
10. **Capability 是执行路由主键**(targetv2 新增),`executor_type` 降格为粗粒度分组
11. **Session 不独占 single-flight**(targetv2 新增): CLI / Server 可直通 Runtime
12. **Project 与 Graph 正交**(targetv2 新增): Project 不参与执行语义
13. **preview cache 与正式 cache 不共享存储**(targetv2 新增)
14. **NodeRegistry 是唯一对外扩展入口**(targetv2 明文化)
