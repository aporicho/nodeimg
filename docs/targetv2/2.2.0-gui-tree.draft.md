# GUI Tree

> GUI Tree 是 GUI 层唯一的结构与状态载体。布局、命中测试、渲染、交互 runtime 都围绕这一棵树工作。Engine Graph 不进入 GUI Tree；GUI Tree 只通过稳定 id 引用 engine 对象。

## 目标

- 用一棵树表达整个 GUI 的结构、层级、绘制顺序和命中路径。
- 所有 UI 临时状态和持久 UI 布局状态都挂到这棵树上。
- 能归属到具体节点的状态挂具体节点。
- 跨节点状态挂到能解释其生命周期和影响范围的最低公共节点。
- 不在 `DemoApp`、controller、panel、overlay system 里分散持有 UI runtime 状态。
- Engine Graph 只保存作品语义，不保存 UI 状态。

## 核心原则

`TreeNode` 同时包含结构和本节点的 runtime 状态：

```rust
pub struct Tree {
    nodes: Vec<Option<TreeNode>>,
    root: Option<TreeNodeId>,
    free: Vec<TreeNodeId>,
}

pub struct TreeNode {
    pub id: StableId,
    pub kind: NodeKind,
    pub props: NodeProps,
    pub style: BoxStyle,
    pub decoration: Option<Decoration>,
    pub rect: Rect,
    pub children: Vec<TreeNodeId>,
    pub local_runtime: NodeLocalRuntime,
    pub runtime_slots: RuntimeSlots,
}
```

`local_runtime` 放所有节点都可能用到的局部状态：

```rust
pub struct NodeLocalRuntime {
    pub hovered: bool,
    pub pressed: bool,
    pub scroll_offset: f32,
    pub content_height: f32,
    pub layout: LayoutRuntime,
    pub animation: AnimationRuntime,
}
```

`runtime_slots` 放节点专属状态，允许 app 自定义类型扩展：

```rust
node.runtime_slots.get::<CanvasRootRuntime>();
node.runtime_slots.ensure::<PanelRuntime>(policy, init);
node.runtime_slots.remove::<OverlayRuntime>();
```

这意味着 runtime 不是 Tree 外的第二套系统；runtime 是 `TreeNode` 的状态包。

最重要的分层：

```text
TreeNode
├── id
├── kind          // 它是哪类 UI 节点
├── props         // 它是什么：文本内容、action_id、engine 引用、accessibility metadata
├── style         // 它如何参与布局
├── rect          // layout 后它实际在哪里
├── children
├── local_runtime // 所有节点通用的“现在怎么样”
└── runtime_slots // 某类节点专属的“现在怎么样”
```

判断一句话：

- `props` 回答“这个东西是什么”。
- `runtime` 回答“这个东西现在怎么样”。

## 状态归属规则

状态挂到能完整解释它生命周期和影响范围的最低公共节点：

| 状态 | 归属 |
| --- | --- |
| focus、capture、modal scope、tab order、last pointer、modifier keys | `root.runtime.RootInteractionRuntime` |
| camera、画布选中、拖线、hovered pin | `canvas_root.runtime.CanvasRootRuntime` |
| 节点卡 position、size、collapsed、z-index | `canvas::node::<engine_node_id>.runtime.CanvasNodeRuntime` |
| 端口 rect cache、派生 hover cache | 对应 `canvas::node::<id>::input/output::<pin>.runtime.PortRuntime` |
| 面板 z、拖拽、resize session | `panel_root.runtime.PanelRootRuntime` |
| 某个 panel 的 rect、visible、collapsed | `panel::<panel_id>.runtime.PanelRuntime` |
| 当前 overlay、overlay stack、dismiss 规则 | `overlay_root.runtime.OverlayRootRuntime` |
| 某个 overlay 的 placement、打开位置 | `overlay::<overlay_id>.runtime.OverlayRuntime` |
| text、caret、selection、composition | 对应 text input 节点的 `TextInputRuntime` |
| button hover/pressed | button 节点的 `local_runtime` 或 `ButtonRuntime` |
| layout dirty、measure cache、scroll extent | 对应节点的 `local_runtime.layout` 或 `LayoutRuntime` |
| cursor blink、transition、spinner progress | 对应节点的 `local_runtime.animation` 或 `AnimationRuntime` |

判断规则：

- 只影响一个节点，并随节点消失而消失：挂该节点。
- 影响一个子树：挂该子树 root。
- 影响多个分支：挂最近公共祖先。
- 依赖业务 owner 生命周期：挂显示节点，但 retention 绑定业务 owner id。
- 需要先有状态才能生成节点：先挂到 root 或对应 subsystem root，再生成具体节点。

## Props 与 Runtime 边界

`props` 和 `runtime` 的边界必须先定死，否则 Tree 会慢慢变成一团混合状态。

| 问题 | 放哪里 |
| --- | --- |
| 这个节点是什么控件 | `kind` |
| 这个控件展示什么文本、图片、engine 引用 | `props` |
| 这个按钮点击后触发什么 action | `props.action_id` |
| 这个输入框提交到哪个 engine 参数 | `props.committed_value_source` |
| 这条连接从哪里连到哪里 | `props.from` / `props.to` |
| 这个端口属于哪个 engine node、哪个 pin、方向是什么 | `props.owner` / `props.pin` / `props.direction` |
| 这个控件现在 hover、pressed、loading、editing 到哪里 | `local_runtime` 或 `runtime_slots` |
| layout 之后的实际 rect、缓存、dirty 标记 | `rect`、`local_runtime.layout` 或 `LayoutRuntime` |
| 可丢弃的绘制缓存、路径缓存、派生视觉状态 | `runtime_slots` |

通俗规则：

- `props` 是“它是什么”，由 `Desc` 每帧声明或由 engine/project 语义数据派生。
- `runtime` 是“它现在怎么样”，由交互、布局、动画、reconcile 在 Tree 内保留。
- 如果一个字段来自 Engine Graph、schema、catalog、action registry，它默认是 `props`，不是 `runtime`。
- 如果一个字段来自用户这一刻的交互、layout 计算、动画播放、输入编辑，它默认是 `runtime`。

## 真源状态与派生状态

一棵树可以表达整个 GUI，但同一个状态不能在树上有多个真源。每个状态必须有且只有一个 canonical owner；其它节点只能保存派生显示值、缓存，或在渲染时直接从真源计算。

规则：

- `root.runtime.RootInteractionRuntime.hovered_node` / `pressed_node` 是指针命中真源。
- `TreeNode.local_runtime.hovered` / `pressed` 只允许作为派生视觉缓存；如果实现可以实时查询 root 真源，也可以不写这些字段。
- `canvas_root.runtime.CanvasRootRuntime.selected_nodes` / `selected_connections` 是画布选择真源。
- `CanvasNodeRuntime`、`ConnectionRuntime` 不保存 `selected` 真源；最多保存 `selected_visual` 这种可丢弃派生缓存。
- `canvas_root.runtime.CanvasRootRuntime.hovered_pin` 是端口 hover 真源；`PortRuntime.hovered_visual` 只表示缓存。
- `ButtonRuntime` 不保存业务 action。按钮 action 属于 `Desc`、`WidgetProps` 或 stable `ActionId`，runtime 只保存按钮交互态。
- Engine 参数的真源在 Engine Graph；GUI Tree 只保存输入框编辑中的 text、caret、selection、composition。
- `ConnectionRuntime` 不保存连接语义真源；`from` / `to` 属于 connection 的 `props`。
- `PortRuntime` 不保存端口语义真源；`owner` / `direction` / `pin` / `connectable` 属于 port 的 `props`。

## 生命周期、持久化与 Undo

runtime slot 使用类型默认策略，并允许实例覆盖：

```rust
pub struct RuntimeSlotPolicy {
    pub retention: RuntimeRetention,
    pub persistence: PersistenceClass,
    pub undo: UndoClass,
}

pub struct RuntimeFieldPolicy {
    pub persistence: PersistenceClass,
    pub undo: UndoClass,
}

pub enum RuntimeRetention {
    DropWhenNodeMissing,
    KeepWhileStableNodeExists,
    KeepWhileOwnerExists(RuntimeOwner),
    KeepForSession,
}

pub enum PersistenceClass {
    Ephemeral,
    ProjectLayout,
    SessionOnly,
}

pub enum UndoClass {
    Undoable,
    NonUndoable,
}
```

默认规则：

- 默认 `DropWhenNodeMissing`。
- 布局类状态 `KeepWhileOwnerExists`。
- root/subsystem runtime `KeepForSession`。
- 临时 overlay/widget 状态默认销毁。
- 项目保存只导出 `ProjectLayout`，不序列化整棵 runtime。
- 持久化和 Undo 是正交维度：`ProjectLayout` 不等于 `Undoable`。
- runtime slot 可以有默认 policy；slot 内字段可以用 `RuntimeFieldPolicy` 覆盖。
- 一个 slot 内混合多类状态时，保存项目和记录 undo 必须按字段策略导出。

典型策略：

| Runtime | Retention | Persistence | Undo |
| --- | --- | --- | --- |
| `ButtonRuntime` | `DropWhenNodeMissing` | `Ephemeral` | `NonUndoable` |
| `TextInputRuntime` | 默认 `KeepWhileStableNodeExists` | `Ephemeral` | `NonUndoable` |
| `PanelRuntime` | `KeepWhileOwnerExists(PanelId)` | `ProjectLayout` | 布局变更 `Undoable`，临时拖拽 `NonUndoable` |
| `CanvasNodeRuntime` | `KeepWhileOwnerExists(EngineNodeId)` | `ProjectLayout` | position/size/collapsed `Undoable`，hover/cache `NonUndoable` |
| `CanvasRootRuntime` | `KeepForSession` | camera 为 `ProjectLayout`，交互为 `Ephemeral` | camera/selection 默认 `NonUndoable`，可由产品规则改为 `Undoable` |
| `OverlayRuntime` | `DropWhenNodeMissing` | `Ephemeral` | `NonUndoable` |
| `NodePaletteRuntime` | `DropWhenNodeMissing` | `Ephemeral` | `NonUndoable` |

字段级例子：

| 字段 | Persistence | Undo |
| --- | --- | --- |
| `CanvasRootRuntime.camera` | `ProjectLayout` | 默认 `NonUndoable` |
| `CanvasRootRuntime.selected_nodes` | `SessionOnly` | 默认 `NonUndoable` |
| `CanvasRootRuntime.active_canvas_interaction` | `Ephemeral` | `NonUndoable` |
| `CanvasNodeRuntime.position` | `ProjectLayout` | `Undoable` |
| `CanvasNodeRuntime.size` | `ProjectLayout` | `Undoable` |
| `CanvasNodeRuntime.selected_visual` | `Ephemeral` | `NonUndoable` |
| `PanelRuntime.rect` | `ProjectLayout` | `Undoable` |
| `TextInputRuntime.text` | `Ephemeral` | `NonUndoable` |

## Owner Liveness

`KeepWhileOwnerExists(owner)` 必须有明确的 owner 判活来源。runtime GC 不能猜 owner 是否存在。

| Owner | 判活来源 |
| --- | --- |
| `StableNodeId` | reconcile 后的 live stable id set |
| `EngineNodeId` | 当前 Engine Graph snapshot |
| `EngineConnectionId` | 当前 Engine Graph snapshot |
| `PanelId` | panel registry 或 panel declaration set |
| `OverlayId` | `overlay_root` 当前 overlay/stack，或 overlay registry |
| `WidgetId` | reconcile 后的 live stable id set，除非显式声明 owner |

## Tree Scope

一棵 GUI Tree 对应一个窗口或一个 `Context`。多窗口场景不是把多个窗口塞进同一棵 GUI Tree，而是每个窗口各有一棵 GUI Tree，并共享同一个 Engine Graph 或 project model。

因此：

- GUI Tree 保存窗口内的 UI 结构、布局、交互和 runtime。
- Engine Graph 保存作品语义，可以被多个 GUI Tree 引用。
- 跨窗口共享状态不能放在某个窗口的 GUI Tree 内，应放在 project/app 语义模型里，再由各窗口 Tree 引用。

## Tree 与外部资源边界

GUI Tree 可以保存资源引用和资源状态，但不直接拥有平台资源：

| 类型 | GUI Tree 中保存 | 实际 owner |
| --- | --- | --- |
| 图片/GPU 纹理 | `ImageResourceId`、尺寸、加载状态、错误信息 | `ResourceRegistry` / renderer |
| Engine artifact | `ArtifactId`、预览状态 | Engine artifact store |
| 文件选择器 | 请求 id、打开中的 overlay 状态 | `PlatformEffectQueue` |
| 剪贴板 | 最近请求状态、目标 widget id | platform adapter |
| 异步任务 | task id、loading/progress/error | task runtime / engine |
| 系统时间 | animation start、duration、progress cache | clock / frame driver |
| IME 会话 | composing text、target text input id | platform IME adapter |

原因是这些对象依赖 OS、GPU、线程或外部生命周期。Tree 负责表达 UI 状态和引用关系，不负责销毁 `wgpu::TextureView`、文件句柄或系统窗口。

## Layout / Animation / Accessibility

这些也属于 GUI 表达，但要分清 Tree 内外边界。

Layout：

```rust
pub struct LayoutRuntime {
    pub dirty: bool,
    pub measure_cache: Option<Size>,
    pub intrinsic_size: Option<Size>,
    pub scroll_extent: Size,
}
```

- `style` 是布局输入。
- `rect` 是布局输出。
- `LayoutRuntime` 是可丢弃的布局缓存和 dirty 状态。
- layout cache 可以随节点销毁，也可以在 stable id 不变时复用。

Animation：

```rust
pub struct AnimationRuntime {
    pub active: bool,
    pub started_at: Option<FrameTime>,
    pub duration_ms: u32,
    pub progress: f32,
}
```

- Tree 保存动画状态。
- clock / frame time 由外部 frame driver 提供。
- cursor blink、spinner、hover transition、overlay fade 都可以挂到节点 runtime。

Accessibility：

```rust
pub struct AccessibilityProps {
    pub role: AccessibilityRole,
    pub label: Option<String>,
    pub focusable: bool,
    pub enabled: bool,
}
```

- accessibility metadata 属于 `props`，因为它描述“这个 UI 是什么”。
- accessibility tree 从 GUI Tree 派生，不单独持有另一套 UI 状态。
- focus、tab order、modal trap 的当前状态仍在 `RootInteractionRuntime`。

## Desc / Reconcile 规则

`Desc` 声明节点需要哪些 runtime slot。reconcile 负责 ensure：

```rust
Desc::Container {
    id,
    props,
    style,
    decoration,
    runtime_slots: vec![
        RuntimeSlotDecl::of::<CanvasRootRuntime>(),
        RuntimeSlotDecl::of::<PanelRootRuntime>(),
    ],
    children,
}
```

Widget 的业务命令由 Desc 侧声明，不进入 runtime：

```rust
Desc::Widget {
    id,
    kind: WidgetKind::Button,
    props: WidgetProps::Button {
        action_id: ActionId::new("node_palette.add.image_gen"),
    },
    runtime_slots: vec![RuntimeSlotDecl::of::<ButtonRuntime>()],
}
```

规则：

- Reconcile 按 stable id 复用 node。
- Reconcile 复用 `TreeNode.local_runtime`。
- Reconcile 自动 ensure Desc 声明的 runtime slot。
- Reconcile 不覆盖已有 runtime 状态，除非 slot 首次创建或显式 reset。
- Reconcile 后执行 runtime GC，根据 retention 和 owner 生命周期清理。
- Runtime store 不依赖 arena `TreeNodeId` 做长期身份。
- Reconcile 不从 runtime 读取 action；事件分发根据 stable node id 或 `ActionId` 查 Desc 侧 action metadata。

## 提供接口

GUI Tree 对 `Context` 提供受控操作接口，不向 App 暴露任意 mutable tree：

```rust
impl Tree {
    pub fn root(&self) -> Option<TreeNodeId>;
    pub fn get(&self, id: TreeNodeId) -> Option<&TreeNode>;
    pub fn get_mut_runtime<T: RuntimeSlot>(&mut self, id: TreeNodeId) -> Option<&mut T>;
    pub fn node_by_stable_id(&self, id: &StableId) -> Option<TreeNodeId>;
    pub fn hit_test(&self, root: TreeNodeId, point: Point) -> HitChain;
    pub fn export_project_layout(&self) -> ProjectLayout;
    pub fn import_project_layout(&mut self, layout: ProjectLayout);
}
```

`Context` 负责把 Tree 接口组合成 GUI 对外 API：

```rust
impl GuiContext {
    pub fn update(&mut self, desc: Desc, input: GuiFrameInput) -> GuiUpdateResult;
    pub fn handle_event(&mut self, event: GuiInputEvent) -> GuiOutput;
    pub fn render(&self, renderer: &mut Renderer, theme: &Theme);
    pub fn hit_test(&self, pos: Point) -> HitChain;
    pub fn export_project_layout(&self) -> ProjectLayout;
    pub fn import_project_layout(&mut self, layout: ProjectLayout);
}
```

## 依赖接口

Tree 本身不依赖 Engine、Shell、wgpu、App。需要外部事实时，通过窄接口从 `Context` 传入：

| 接口 | 用途 |
| --- | --- |
| `TextMeasure` | layout 阶段测量文本。 |
| `ThemeProvider` | widget build 和 paint 使用 theme token。 |
| `FrameClock` | animation runtime 更新 progress。 |
| `ResourceResolver` | paint 阶段把 resource id 解析为 texture/status。 |
| `OwnerLivenessProvider` | runtime GC 判断 owner 是否仍存在。 |
| `PlatformAdapter` | Tree 不直接使用；`Context` 把 Tree 产生的 effect 转给 shell。 |

## 文件结构设计

GUI Tree 相关文件只放 Tree 模型、reconcile、runtime slots、layout、hit、paint：

```text
gui/src/tree/
├── mod.rs
├── tree.rs
├── node.rs
├── id.rs
├── desc.rs
├── props.rs
├── reconcile.rs
├── runtime_slots.rs
├── runtime_policy.rs
├── owner_liveness.rs
├── gc.rs
├── hit.rs
├── scroll.rs
├── paint.rs
├── paint_helpers.rs
└── layout/
    ├── mod.rs
    ├── types.rs
    ├── measure.rs
    ├── arrange.rs
    └── layout.rs
```

文件职责：

- `tree.rs`：arena、root、children、stable id 索引。
- `node.rs`：`TreeNode`、`NodeKind`、`NodeLocalRuntime`。
- `id.rs`：`TreeNodeId`、`StableId`。
- `desc.rs`：声明式输入树。
- `props.rs`：`NodeProps`、accessibility metadata、action metadata、engine 引用。
- `reconcile.rs`：`Desc -> Tree`，复用节点并 ensure runtime slots。
- `runtime_slots.rs`：typed runtime slot store。
- `runtime_policy.rs`：retention、persistence、undo、field policy。
- `owner_liveness.rs`：runtime GC 的 owner 判活接口。
- `gc.rs`：节点和 runtime slot 回收。
- `hit.rs`：命中测试与 hit chain。
- `scroll.rs`：scroll offset、scroll extent、scroll input reducer。
- `paint.rs`：Tree 到 draw command / renderer 调用。
- `layout/`：measure、arrange、layout cache。


## 与 Engine Graph 的关系

GUI Tree 可以引用 engine 对象，但不拥有 engine 语义状态：

```text
Engine Graph:
  nodes
  connections
  params
  artifacts

GUI Tree:
  rect
  camera
  position
  selected_nodes / selected_connections
  hovered_node / pressed_node
  overlay
  text input editing buffer
  resource id / artifact id / loading state
```

例子：

```text
EngineParam(engine_node::1, "brightness")
```

表示 text input 的提交目标在 Engine Graph；但编辑中字符串、caret、selection 仍在 GUI Tree。

## Node Palette 示例流程

```text
用户双击空白画布
-> root.runtime.RootInteractionRuntime 更新 click_memory
-> hit chain 判断目标属于 canvas_root 空白区域
-> overlay_root.runtime.OverlayRootRuntime.current_overlay = "node_palette"
-> reconcile 生成 overlay::node_palette
-> 用户点击 node_palette::add::image_gen
-> event dispatcher 根据 Button 的 action_id 找到 AddNode("image_gen")
-> controller 调 engine.add_node("image_gen") -> engine_node::<new_id>
-> view 生成 canvas::node::<new_id>
-> reconcile ensure CanvasNodeRuntime
-> CanvasNodeRuntime.position = overlay.opened_at_canvas
-> overlay_root.runtime.current_overlay = null
```

## 迁移方向

- `PanelRuntimeStore` 已删除；panel 状态挂在 `panel_root` 和 `panel::<id>` 的 runtime slots。
- `PopupSystem` 已迁入 `overlay/`；overlay 状态由正式 overlay system 管理，后续再细化为 `overlay_root` / `overlay::<id>` runtime slots。
- 当前 `TextInputStore` 迁移为对应 text input 节点的 `TextInputRuntime` slot。
- 当前 `DemoApp.camera` 迁移为 `canvas_root.runtime.CanvasRootRuntime.camera`。
- 当前节点库 panel prototype 删除，改为 `overlay_root` 下的 `overlay::node_palette`。
- `DemoApp` 不再持有 UI runtime 状态，只转发事件、调用 controller、驱动 update/render。
