# 引擎共享契约

> GUI、CLI、AI 操作员共用的一套引擎边界。第一版以同进程函数调用 + 广播事件为前提,不定义网络协议。

> **targetv2 说明:** 本文档在 target 同名文档基础上做**增量修订**,只描述 targetv2 引入的变更。未提到的字段、请求、响应均继承 target 原稿,行为不变。完整版本参见 `docs/target/0.0.1-engine-contract.md` 直到迁移完毕。

---

## 1. 目标与边界

本文件定义三类前端与引擎之间的唯一共享 contract:

- GUI → 引擎(经 **Session** 层)
- CLI → 引擎(**直通 Runtime**,不经 Session)
- AI 操作员 → 引擎(经 Session 层,与 GUI 共享一个 Session 实例)

本文件纳入的能力范围:

- Project 生命周期
- Graph 编辑
- Execution 执行(含 `EvaluationFidelity` 字段)
- Artifact 产物
- Backend 可用性
- Event 事件订阅

本文件明确不纳入的内容:

- 节点布局、视口、选中态(归 GUI / App 层)
- Session 内部结构(归 `4.12.0-session.md`)
- Runtime 内部调度(归 `4.1.2-runtime.md`)

## 2. 调用模型

### 2.1 总体模型

- **命令(Command)**: 会修改引擎状态;成功后可触发事件
- **查询(Query)**: 只读快照;不修改状态,不触发事件
- **事件(Event)**: 引擎通过广播流异步推送给订阅者

### 2.2 交互方式

- **同步命令**: 图编辑、项目切换等操作在状态提交后返回
- **异步命令**: `execute`、`ensure_backend`、`reconnect_backend` 在"请求已受理"后返回;后续进度与终态通过事件通知
- **查询**: 返回调用时刻的一致性快照
- **事件订阅**: 每个调用方获得独立事件流

### 2.3 前端路径差异(targetv2 新增)

不同前端对 Facade 的访问路径不同:

| 前端 | 访问路径 | 备注 |
|------|---------|------|
| GUI | `EngineFacade + SessionHandle` | 自动绑定到当前 Session |
| AI 操作员 | `EngineFacade + SessionHandle` | 共享 GUI 的 Session |
| CLI | `EngineFacade`(无 Session) | 直接调用 Runtime |
| Server | `EngineFacade`(无 Session) | 直接调用 Runtime |

GUI 通过 `SessionHandle` 获得的能力(相对 CLI 多出来的):

- preview / undo / redo 栈
- preview hot cache
- 交互事件流(`InteractionEvent`)
- UI 选中态、焦点态

CLI / Server **不需要**这些能力,直接调 `execute` 即可,走 Runtime 正常 `single-flight` 约束。

## 3. Facade 轮廓

targetv2 引入的字段变更(相对 target):

### 3.1 execute

`ExecuteRequest` 新增 `fidelity` 字段,对外层可选(默认 Full):

```rust
struct ExecuteRequest {
    target: ExecuteTarget,
    mode: ExecutionMode,
    /// targetv2 新增;对 EngineFacade 层是 Option(默认 Full);
    /// 进入 Runtime::try_start_run 时必填(由 Scheduler facade 填充默认值)
    fidelity: Option<EvaluationFidelity>,
}
```

**语义:**

- GUI / AI 操作员在交互路径上通常显式发送 `fidelity: Some(Preview { max_side: Some(1024), precision: Float16 })`
- 导出路径发送 `fidelity: Some(Full)` 或省略(默认 Full)
- **CLI 通常省略**——使用 None,由 Scheduler facade 填充为 `Full`
- Runtime 内部接口(`try_start_run`)**必填** `fidelity: EvaluationFidelity`——内部与对外接口的默认值填充在 Scheduler facade 层完成

**这让 CLI 使用体验更友好**(不需要每次都显式传 fidelity),同时保证内部类型精确(Runtime 永远拿到非空值)。

详见 `0.1.2-interaction-loop.md` §2.2。

### 3.2 set_param

`SetParamRequest` 的 `preview: bool` 字段保留,但其语义**精确化**为:

- `preview = true` → Session 层不提交真正的 `Graph` 编辑,而是在 preview 层做参数 overlay,下一次 execute 请求会带 overlay 参数
- `preview = false` → 正式提交到 `GraphController`,触发 `GraphChangedEvent`

此字段**仅** GUI / AI 操作员使用,CLI 不使用。

### 3.3 get_execution_state

`ExecutionState` 的 `current: Option<RunningExecution>` 中 `RunningExecution` 新增 `fidelity: EvaluationFidelity` 字段。

### 3.4 subscribe_events

事件流包含 **两类**事件:

- **`EngineEvent`**: Runtime / Planner 发出的事件,三端对等
- **`SessionEvent`**(targetv2 新增): 仅 GUI / AI 操作员通过 Session 路径获得的事件——例如 `PreviewCacheUpdated`、`InteractionAck`

CLI / Server 订阅时**只**收 `EngineEvent`,不收 `SessionEvent`。
