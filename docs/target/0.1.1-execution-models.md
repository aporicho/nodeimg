## §1 执行请求与结果

### §1.1 ExecutionRequest

```rust
struct ExecutionRequest {
    run_id: RunId,
    node_id: NodeId,
    node_def: Arc<NodeDef>,
    inputs: ExecutionInputs,
    exec_signature: ExecSignature,
    generation: GenerationId,
    timeout_ms: Option<u64>,
    cancel_token: CancelToken,
    progress_sink: ProgressSink,
}
```

字段语义：

- `run_id`：所属执行轮次。
- `node_id`：当前执行的节点实例。
- `node_def`：权威节点静态定义。
- `inputs`：已解析完成的最终输入值。
- `exec_signature`：本次语义计算签名（见 §3）。
- `generation`：缓存代际，仅用于并发防回灌。
- `timeout_ms`：节点级超时；默认来自 `NodeDef.execution.timeout`。
- `cancel_token`：节点级取消令牌。
- `progress_sink`：节点级进度上报通道。

### §1.2 ExecutionInputs / ExecutionOutputs

```rust
type ExecutionInputs = HashMap<String, Value>;
type ExecutionOutputs = HashMap<String, Value>;
```

约束：

1. key 对应正式接口名称。
2. 输入 key 对应正式输入口名称；输出 key 对应正式输出口名称。
3. 参数输出接口的值不由执行器手工构造，而由引擎在正式接口层补齐。

## §2 执行状态

### §2.1 ExecutionStatus

```rust
enum ExecutionStatus {
    Idle,
    Running,
    Cancelling,
}
```

### §2.2 RunningExecution / ExecutionState

```rust
struct RunningExecution {
    execution_id: ExecutionId,
    target: ExecuteTarget,
    mode: ExecutionMode,
}

struct ExecutionState {
    status: ExecutionStatus,
    current: Option<RunningExecution>,
}
```

### §2.3 ExecutionResultSummary

```rust
struct ExecutionResultSummary {
    execution_id: ExecutionId,
    status: ExecutionTerminalStatus,
    target: ExecuteTarget,
    mode: ExecutionMode,
    finished_nodes: Vec<NodeId>,
    failed_nodes: Vec<NodeId>,
}

enum ExecutionTerminalStatus {
    Finished,
    Cancelled,
    Error,
}
```

### §2.4 核心运行规则

1. **single-flight**：同一时刻最多一个活动执行。
2. 取消粒度：**run 级 + node 级**。
3. 终态必须稳定落为：`Finished / Cancelled / Error` 之一。

## §3 语义签名与缓存键

### §3.1 ExecSignature

> 语义签名，回答“这是否是同一次语义计算”。

```rust
struct ExecSignature {
    hash: u128,
}
```

构造规则：

1. 基于**上游签名的传递闭包** + **本节点最终有效参数 hash**。
2. **不对 `Value` 本体做 hash**。
3. **不含 `generation`**。
4. 首版 hash 算法固定为 `xxHash3-128`。

### §3.2 CacheKey

> 缓存键，回答“某个输出在某个 generation 下的可复用缓存条目”。

```rust
struct CacheKey {
    node_id: NodeId,
    output_pin: String,
    exec_signature: ExecSignature,
    generation: GenerationId,
}
```

设计约束：

1. **语义签名与缓存键严格分离**。
2. `generation` 只存在于 `CacheKey` 层，不参与 `ExecSignature`。
3. 同一语义在不同 `generation` 下的 `ExecSignature` 必须相同。

### §3.3 GenerationId

```rust
struct GenerationId(u64);
```

推进规则：

- **仅**以下操作触发 `generation + 1`：
  - `clear_cache`
  - `replace_graph`

其他操作（undo / redo、参数修改、节点增删、连线调整等）不触发 generation bump，而是通过签名变化自然失效。

## §5 执行策略

### §5.1 ExecutionPolicy

```rust
struct ExecutionPolicy {
    timeout_ms: Option<u64>,
    cache: Option<CachePolicy>,
    artifact_policy: Option<ArtifactPolicy>,
    trigger_policy: TriggerPolicy,
    retry_policy: RetryPolicy,
}
```

说明：

- `cache`：引擎默认推导 + 节点可选覆盖。
- `artifact_policy`：引擎默认推导 + 节点可选覆盖。
- `trigger_policy` / `retry_policy`：节点级显式策略。

### §5.2 CachePolicy

```rust
enum CachePolicy {
    Disabled,
    SuccessOnly,
    SuccessAndHandle,
}
```

含义：

- `Disabled`：不缓存结果。
- `SuccessOnly`：缓存成功结果。
- `SuccessAndHandle`：缓存成功结果，也允许缓存 `Handle`。

默认推导说明：

- 首版缓存行为由引擎默认推导，`NodeDef.execution.cache` 只做节点级可选覆盖；
- 本文档当前冻结三档枚举值与“允许节点覆盖”这一能力，不冻结更细的默认推导矩阵；
- 若未来需要 TTL（生存时间，TTL）、错误缓存或短期退避，应先修改不变量层，再扩展 `CachePolicy` 表达能力。

### §5.3 ArtifactPolicy

```rust
enum ArtifactPolicy {
    None,
    Persist,
}
```

默认推导：

- `purity = Pure` → `None`
- `purity = Impure` → `Persist`

例外：

- 导出型节点（如 `save_image`，具有文件 I/O 副作用）不靠 `purity` 判定产物登记；
- 这类节点是否登记产物、是否进入项目内版本链路，由其导出语义与 `ArtifactManager`（产物管理器，ArtifactManager）规则共同决定。

### §5.4 TriggerPolicy

```rust
enum TriggerPolicy {
    AutoAndManual,
    ManualOnly,
}
```

### §5.5 RetryPolicy

```rust
enum RetryPolicy {
    NoRetry,
    Retry {
        max_attempts: u32,
        backoff: RetryBackoff,
        retry_on: Vec<RetryCondition>,
    },
}

enum RetryBackoff {
    Fixed,
    Exponential,
}

enum RetryCondition {
    Timeout,
    Network,
    RateLimit,
    ServiceUnavailable,
}
```

## §6 列表执行规则

### §6.1 首版列表执行范围

- 首版正式支持 `List<Image>` 与 `List<Json>`。
- 图像处理节点默认支持 `List<Image>`。

### §6.2 输入提升与降级

1. `Atomic(T)` 可自动提升为单元素 `List(T)`。
2. `List(T)` 不自动降级为 `Atomic(T)`。

### §6.3 图像节点的列表语义

1. 图像节点遇到 `List<Image>` 时默认逐帧 map 执行。
2. 输出默认保持输入形态：
   - 单张输入 → 单张输出
   - 列表输入 → 列表输出
3. 多列表长度不一致时，不做隐式广播/循环/补齐；由显式节点控制。

## §7 错误模型

```rust
enum ExecutorError {
    Unavailable { message: String },
    InvalidInput { message: String },
    Timeout,
    Cancelled,
    RuntimeFailed { message: String },
}
```

说明：

- `ExecutorError` 是执行器边界上的稳定错误类型；
- 向前端暴露时由运行时转译为 `NodeError` / `ExecutionError` 等更高层事件或错误模型。
