# 执行器统一 contract

> 调度器与图像 / AI / API 执行器之间的统一边界。定义执行请求、执行输出、取消、进度与注册表协议。

---

## 文档状态

本文件是 **.impl**。

- 统一执行器接口已确定；
- 调度器只依赖本文件定义的 contract；
- 图像 / AI / API 执行器都是本 contract 的实现；
- 具体内部实现可继续细化，但不应再改变边界语义。

---

## 定义

执行器 contract 是**调度运行时调用单节点执行能力的统一协议**。

它解决三件事：

1. 调度器如何以统一方式调用不同执行器；
2. 单节点执行如何接收输入、取消、超时和进度通道；
3. 单节点执行如何返回多输出结果，而不掺入缓存或产物副作用。

一句话：

> **执行器 contract = 调度器与具体执行器之间的最小稳定调用边界。**

---

## 职责边界

### 属于执行器 contract

- 统一执行器接口
- 执行请求模型
- 执行输出模型
- 节点级取消与进度协议
- 执行器注册与按 `executor_type` 路由协议

### 不属于执行器 contract

- 图编辑
- 执行计划生成
- 缓存命中判断
- 产物持久化写入
- 前端事件订阅机制

说明：

- 缓存与产物由调度运行时编排；
- 执行器只负责“执行这个节点并返回结果”。

## 提供接口

### 统一执行器接口

```rust
trait Executor: Send + Sync {
    fn execute(&self, request: ExecutionRequest) -> Result<ExecutionOutputs, ExecutorError>;
    fn health(&self) -> ExecutorHealth;
}
```

### 接口语义

#### `execute(request)`

- 输入：统一 `ExecutionRequest`（执行请求，ExecutionRequest）
- 输出：`ExecutionOutputs`（执行输出映射，ExecutionOutputs）
- 副作用：允许访问本执行器下游运行时，但**不允许**直接写缓存或产物
- 取消：通过 `request.cancel_token`（取消令牌，cancel token）感知
- 进度：通过 `request.progress_sink`（进度通道，progress sink）上报

#### `health()`

- 返回执行器自身可用性摘要
- 仅用于诊断、启动检查或 UI 状态显示
- 不参与调度主路径判定

---

## 依赖接口

### 对事件系统

执行器本身不直接依赖事件总线对外发最终事件；若需要节点级中间进度，统一写入 `request.progress_sink`，由运行时转译为事件。

### 对下游运行时 / Provider

- 图像执行器依赖 GPU / CPU 执行上下文
- AI 执行器依赖 `AIRuntime`（AI 运行时，AIRuntime）
- API 执行器依赖 `Provider`（提供方，Provider）

这些属于**执行器内部依赖**，不进入调度器边界。

## 共享模型

权威共享模型另见：`0.1.1-execution-models.md`。

### ExecutionRequest

```rust
struct ExecutionRequest {
    run_id: RunId,
    node_id: NodeId,
    node_def: Arc<NodeDef>,
    inputs: ExecutionInputs,
    exec_signature: ExecSignature,
    generation: GenerationId,
    timeout_ms: Option<u64>,
    cancel_token: CancelToken,
    progress_sink: ProgressSink,
}
```

说明：

- `node_def` 是权威节点定义；
- `inputs` 是已解析完成的正式输入值；
- `timeout_ms` 默认来自 `NodeDef.execution`；
- `generation` 用于与缓存层配合做防回灌；
- 产物策略、缓存策略也从 `node_def.execution` 读取，但由运行时解释，不由执行器解释。

### ExecutionInputs

```rust
type ExecutionInputs = HashMap<String, Value>;
```

### ExecutionOutputs

```rust
type ExecutionOutputs = HashMap<String, Value>;
```

约束：

- key 必须对应节点正式输出口名称；
- 多输出节点必须显式返回全部已成功产出的输出；
- 参数输出接口不由执行器构造，而由引擎在正式接口层补齐。

### ProgressSink

```rust
trait ProgressSink: Send + Sync {
    fn report(&self, event: ExecutorProgressEvent);
}
```

### ExecutorProgressEvent

```rust
enum ExecutorProgressEvent {
    Message { text: String },
    Fraction { current: u32, total: u32 },
    Preview { output: String, value: Value },
}
```

### ExecutorError

```rust
enum ExecutorError {
    Unavailable { message: String },
    InvalidInput { message: String },
    Timeout,
    Cancelled,
    RuntimeFailed { message: String },
}
```

### ExecutorHealth

```rust
enum ExecutorHealth {
    Ready,
    Degraded { message: String },
    Unavailable { message: String },
}
```

## 执行器注册表

### 提供接口

```rust
trait ExecutorRegistry {
    fn register(&mut self, executor_type: ExecutorType, executor: Arc<dyn Executor>);
    fn get_executor(&self, executor_type: ExecutorType) -> Option<Arc<dyn Executor>>;
}
```

### 设计约束

- 首版权威分类来源是 `NodeDef.executor_type`；
- 每个 `ExecutorType` 至少对应一个执行器；
- 运行期不支持热插拔；
- 缺失映射时由调度器转为稳定错误，而不是 panic（致命崩溃，panic）。

---

## 错误与事件

- 执行器不直接向前端广播最终事件；
- 执行器只通过 `ProgressSink` 上报节点级过程信息；
- 运行时将 `ExecutorError` 转译为 `NodeError` / `ExecutionError`。
