# 数据模型

> **Tier 1 真源。** 核心共享数据结构的唯一权威定义。受 `architecture-invariants.md` 管辖。

- 所有 `4.x.x` 模块文档只能**引用**本文档中的类型，不得重新定义。
- 执行域模型（`ExecSignature`、`CacheKey`、`ExecutionRequest` 等）见 `0.1.1`。
- 历史版本见 `0.1.0-models.legacy.md`，仅供参考。

## §1 类型系统

### §1.1 AtomicType

> 封闭枚举，13 种。新增、删除或修改原子类型均为破坏性变更（须先改 `architecture-invariants.md` 真源 ③）。

```rust
enum AtomicType {
    Image, Mask, Float, Int, Bool, Color, String,
    Handle, Video, Audio, Path, Bytes, Json,
}
```

| 原子类型 | 分类 | Rust 类型 | 首版 `List<T>` |
|---------|------|----------|---------------|
| `Image` | 媒体 | `ImageValue` | **开放** |
| `Mask` | 媒体 | `MaskValue` | 预留 |
| `Float` | 标量 | `f32` | 预留 |
| `Int` | 标量 | `i64` | 预留 |
| `Bool` | 标量 | `bool` | 不开放 |
| `Color` | 标量 | `[f32; 4]` | 不开放 |
| `String` | 标量 | `String` | 预留 |
| `Handle` | 远端引用 | `Handle` | 不开放 |
| `Video` | 媒体 | `VideoValue` [待确认] | 不开放 |
| `Audio` | 媒体 | `AudioValue` [待确认] | 不开放 |
| `Path` | 资源引用 | `PathBuf` | 预留 |
| `Bytes` | 交换格式 | `Vec<u8>` | 不开放 |
| `Json` | 结构化数据 | `serde_json::Value` | **开放** |

**首版 `List<T>` 列含义：**
- **开放** = 首版允许 `List(T)`。
- **预留** = 类型系统层面可支持，首版禁止，启用须更新本文档白名单。
- **不开放** = 不允许进入 `List<T>`，变更须先改本文档。

**类型补充说明：**
- `Image`：内含 CPU（`DynamicImage`）+ GPU（`GpuTexture`）双缓存，`OnceLock` 懒转换；任一表示被首次请求时从另一表示自动转换（如节点请求 GPU 纹理时自动从 CPU 图像上传）。
- `Mask`：语义独立于 `Image`，不是 `Image` 的子类型。
- `Video` / `Audio`：运行时表示待确认。
- `Handle`：Python VRAM 引用凭证（见 §1.4）。

**`Path` / `Bytes` / `Json` 主语义：**

| 类型 | 主语义 | 说明 |
|------|--------|------|
| `Path` | 资源引用 | 指向文件系统路径，不是媒体内容本体 |
| `Bytes` | 底层交换格式 | 用于导入导出、编码结果、网络载荷等；首版不鼓励作为常规处理链路中间值 |
| `Json` | 正式可连线数据 | 可作为节点输入/输出在图中流动，不仅仅是配置；因此首版允许 `List<Json>` |

### §1.2 DataType

> 两层结构：原子类型 + 类型构造器。

```rust
enum DataType {
    Atomic(AtomicType),
    List(AtomicType),
}
```

**约束：**
1. 禁止嵌套——`List` 的参数只能是 `AtomicType`，不能是 `DataType`，因此 `List<List<T>>` 不存在。
2. 首版白名单——仅允许 `List(Image)` 和 `List(Json)`。
3. 类型匹配——连接校验要求 `DataType` 完全相等；`Atomic(Image)` 与 `List(Image)` 不兼容。
4. 扩展路径——新增原子类型自动获得 `Atomic(T)`；是否开放 `List(T)` 由 §1.1 能力声明 + 白名单共同决定。

### §1.3 Value

> 运行时值。变体与 `AtomicType` 一一对应，另加 `List` 容器变体。

```rust
enum Value {
    // 原子变体
    Image(ImageValue),   
    Mask(MaskValue),
    Float(f32),
    Int(i64),
    Bool(bool),          
    Color([f32; 4]),
    String(String),      
    Handle(Handle),
    Video(VideoValue),   
    Audio(AudioValue),
    Path(PathBuf),
    Bytes(Vec<u8>),
    Json(serde_json::Value),

    // 容器变体
    List { element_type: AtomicType, items: Vec<Value> },
}
```

**约束：**
1. **无全局 Hash / Eq**——`Value` 不实现 `Hash` 或 `Eq`。含 GPU 资源或大数据的变体无法安全 hash。`HashMap<Value, _>` 不存在。计算身份由 `ExecSignature`（见 `0.1.1`）承担。
2. `List.items` 中每个元素须匹配 `element_type` 对应的原子变体（运行时校验）。
3. `List.element_type` 须在首版白名单中（见 §1.2 约束 2）。

> *设计备忘：* 大对象（Image/Video/Audio）内部用 `Arc` 共享避免拷贝，API 层统一表现为 `Value`。标量值可在业务逻辑中直接比较，但这不等于 `Value` 拥有统一的全局 `Hash/Eq`。

### §1.4 Handle

> Python VRAM 引用凭证，不含实际数据。

```rust
Handle { id: u64, kind: String }
```

- `kind`：远端资源语义（`"model"` / `"clip"` / `"vae"` / `"conditioning"` / `"latent"` 等），由 Python 端定义，**开放字符串**。
- 连接校验：`kind` 匹配是 Handle 引脚连接的必要类型条件（运行时有效性等其他条件另行检查）。

### §1.5 Constraint

> 参数的合法性约束，附加在 `ParamDef` 上。**开放类型**，通过 `ConstraintRegistry` 注册扩展。

```rust
Constraint { type_id: String, params: JsonValue }
```

| type_id | params | 说明 |
|---------|--------|------|
| `range` | `{ min, max }` | 数值范围 |
| `step` | `{ value }` | 数值步长 |
| `enum` | `{ options: [...] }` | 枚举选项 |
| `must_exist` | `{}` | 路径或资源必须存在 |
| `multiline` | `{}` | 多行文本输入 |
| `placeholder` | `{ text }` | 轻量输入提示文本 |
| `secret` | `{}` | 敏感输入，不应明文回显 |
| `file_path` | `{ extensions: [...], mode?: "open" | "save" }` | 文件路径输入与扩展名过滤 |
| `advanced` | `{}` | 高级参数提示 |
| `read_only` | `{}` | 只读参数提示 |

新增约束类型通过注册表扩展，无需修改核心代码。

边界：

- `Constraint` 允许表达**数据合法性规则**与**跨前端稳定的轻量控件提示**；
- `Constraint` 不表达参数显示位置、节点布局、控件尺寸、折叠状态等 GUI 私有渲染细节；
- 参数显示位置由 `PresentationProvider`（展示提供器，PresentationProvider）负责。

> *设计备忘：* `Constraint` 开放与 `AtomicType` 封闭不矛盾——前者是参数校验规则（需求无界），后者是引脚间数据种类（需求有界）。

## §2 节点定义层

### §2.1 NodeSourceKind

```rust
enum NodeSourceKind {
    Builtin,
    Python,
    Api,
}
```

语义：

- `Builtin`：Rust 内置图像节点来源；
- `Python`：Python 节点来源；
- `Api`：API Provider（提供方，Provider）来源。

### §2.2 Purity

```rust
enum Purity {
    Pure,
    Impure,
}
```

约束：

1. `Purity` 独立于 `executor_type`（执行器类型，executor_type）；
2. 值域固定为二元，不允许静默扩展；
3. `purity` 判定源 = `NodeDef` 必填字段，由节点作者显式声明。

### §2.3 InputPinDef / OutputPinDef

```rust
struct InputPinDef {
    name: String,
    data_type: DataType,
    required: bool,
}

struct OutputPinDef {
    name: String,
    data_type: DataType,
}
```

约束：

- `required` 只存在于输入口，输出口不定义该字段；
- `InputPinDef` / `OutputPinDef` 分离，避免把无意义字段塞进统一 `PinDef`。

### §2.4 ParamExpose

```rust
enum ParamExpose {
    Control,
    Input,
    Output,
}
```

说明：

- `Control`：参数渲染为控件；
- `Input`：参数暴露为参数输入接口；
- `Output`：参数暴露为参数输出接口。

### §2.5 ParamDef

```rust
struct ParamDef {
    name: String,
    data_type: DataType,
    default: Value,
    expose: Vec<ParamExpose>,
    constraints: Vec<Constraint>,
}
```

约束：

1. `default` 必填；
2. `expose` 为**非空**多值集合；
3. 复杂媒体值与外部引用值默认只允许空默认值；
4. `Json` 与 `Path` 允许非空默认值；
5. `constraints` 为列表，允许同时携带多条规则。

### §2.6 NodeDef

```rust
struct NodeDef {
    type_id: String,
    version: u32,
    source: NodeSourceKind,
    name: String,
    category: String,
    description: Option<String>,
    tags: Vec<String>,
    icon: Option<String>,
    executor_type: ExecutorType,
    purity: Purity,
    inputs: Vec<InputPinDef>,
    outputs: Vec<OutputPinDef>,
    params: Vec<ParamDef>,
    execution: ExecutionPolicy,
}
```

说明：

- `category` 使用路径字符串，如 `image/color`、`ai/generation`；
- `tags` 为自由字符串数组；
- `icon` 保存规范化图标 id（标识符，id），而不是 GUI 资源对象；
- `execution` 的正式定义见 `0.1.1-execution-models.md`。

`NodeDef` 负责：

- 静态身份；
- 执行归类；
- 纯/非纯语义；
- 静态输入输出；
- 静态参数；
- 默认执行策略；
- 轻展示元数据。

`NodeDef` 不负责：

- 动态参数 schema（参数结构，schema）；
- 参数显示位置；
- GUI 渲染细节；
- 运行时状态。

## §3 图模型层

### §3.1 Graph

```rust
struct Graph {
    nodes: HashMap<NodeId, Node>,
    connections: Vec<Connection>,
}
```

约束：

1. `Graph = (nodes, connections)`；
2. `Graph` 是不可变值类型；
3. `Graph` 不含任何布局信息；
4. 图必须满足有向无环、类型匹配、单输入约束。

### §3.2 Node

```rust
struct Node {
    id: NodeId,
    type_id: String,
    params: HashMap<String, Value>,
}
```

说明：

- `type_id` 指向 `NodeDef.type_id`；
- `params` 仅存实例级当前参数值；
- 默认值从 `NodeDef.params` 查询；
- 布局、视口、选中态等不属于 `Node`。

### §3.3 Connection

```rust
struct Connection {
    from_node: NodeId,
    from_pin: String,
    to_node: NodeId,
    to_pin: String,
}
```

约束：

- 连接两端的数据类型必须兼容；
- 单输入口最多一条入边；
- 参数输入/输出接口若被暴露，应与普通引脚一起参与正式接口校验。

## §4 节点统一注册框架

```rust
NodeSource -> Vec<NodeRegistration>

struct NodeRegistration {
    static_def: NodeDef,
    schema_provider: Option<SchemaProvider>,
    presentation_provider: Option<PresentationProvider>,
}
```

约束：

1. 所有节点来源统一产出 `NodeRegistration`；
2. 一个来源可返回多个节点；
3. `schema_provider` / `presentation_provider` 都是可选层，且按**节点类型**提供；
4. 不提供自定义执行绑定入口；
5. 执行统一依赖 `NodeDef.executor_type`。

默认回退：

- 无 `schema_provider` → 使用 `NodeDef.params`；
- 无 `presentation_provider` → 使用统一默认展示规则。
