对，你的纠正是对的。我们现在不应该说“缺 `ParamRow`、`PortPin` 这种节点控件”，而应该说：

**我们缺的是一套更完整的通用控件/设计系统能力。节点只是第一个会暴露这些缺口的复杂场景。**

我用 24 轮推理后，结论是：当前不是“控件数量完全不够”，而是 **已有控件偏基础表单，缺少通用的可组合 UI 原子能力**。

当前已有：

- `Button`
- `Label`
- `TextInput`
- `NumberInput`
- `Slider`
- `Checkbox`
- `Toggle`
- `Radio`
- `Dropdown`
- `Separator`
- `ImageViewer`
- `Panel`
- `Group`
- `Collapsible`
- `ListView`
- `ScrollArea`

所以我们不是从零开始。真正缺的是下面这些通用能力。

**第一类：文本布局能力**
这是最优先的通用能力。

现在缺：

```text
单行文本
固定宽度文本
clip
ellipsis
文本对齐
可控 line-height
```

对应 CSS 是：

```css
white-space: nowrap;
overflow: hidden;
text-overflow: ellipsis;
```

应该做成通用能力，而不是节点专用：

```text
TruncatedText
InlineText
TextOverflow::Clip
TextOverflow::Ellipsis
TextAlign
```

它会被这些地方复用：

- Button label
- Dropdown selected text
- List item
- Panel title
- 节点标题
- pin label
- 参数名
- 参数值

所以第一项应该是 **文本溢出和文本约束能力**。

---

**第二类：控件尺寸 / 密度体系**

当前控件大多是普通表单尺寸。节点、工具栏、属性面板都需要紧凑模式。

缺：

```text
ControlSize::Small
ControlSize::Medium
ControlSize::Large
Density::Compact
Density::Regular
```

或者更简单：

```text
size: ControlSize
compact: bool
```

这不是节点专用。它应该影响：

- padding
- font size
- row height
- icon size
- radius
- gap

否则后面每个场景都会自己写一套 magic number。

---

**第三类：Field / Form Row 组合能力**

不要叫 `ParamRow`，那是节点语言。通用叫法应该是：

```text
FieldRow
FormField
PropertyRow
```

它表达的是：

```text
label | control | optional helper/error/status
```

用途：

- 节点参数行
- 右侧属性面板
- 设置面板
- inspector
- 表单

需要支持：

- label 区域
- value/control 区域
- helper text
- error text
- disabled
- dirty
- required
- compact layout
- label width / value width 策略

节点参数只是 `FieldRow` 的一个使用者。

---

**第四类：图标与图标按钮**

现在 `LeafKind::Icon` 类型存在，`ButtonProps` 也有 `icon` 字段，但实际控件体系还没有完整的图标按钮能力。

缺：

```text

IconButton
Button icon + text layout
```

通用用途：

- toolbar
- panel close
- collapse arrow
- dropdown arrow
- node action button
- reset value
- delete / add / duplicate
- warning/error indicator

需要先让 icon 在 widget 层真正可用，否则后面很多小控件都会只能用文字凑。

## 结论：真正缺的通用控件/能力清单

按优先级排序：

1. **文本溢出能力**
   `TruncatedText` / `TextOverflow` / `TextAlign`

2. **控件尺寸体系**
   `ControlSize` / `Density` / compact tokens

3. **通用字段行**
   `FieldRow` / `FormField` / `PropertyRow`

4. **图标体系**
   `Icon` 渲染完善 + `IconButton` + button icon layout

5. **小型状态/标签控件**
   `Chip` / `Badge` / `StatusDot`

6. **浮层内容控件**
   `Popover` / `Menu` / `MenuItem` / `Tooltip`

7. **紧凑选择控件**
   `SegmentedControl` / `InlineSelect`

8. **颜色控件**
   `ColorSwatch`，后续 `ColorPicker`

9. **资源/值展示控件**
   `ValueChip` / `AssetChip` / `HandleChip`

10. **输入控件增强**
   compact / readonly / prefix / suffix / error / helper

## 第一项应该做什么

第一项不应该做 `PortPin`，也不应该做 `ParamRow`。

第一项应该做：

```text
通用文本约束与溢出能力
```

也就是：

```text
TextOverflow
TruncatedText
TextAlign
```

原因很简单：所有控件都会依赖它。没有它，后面做 `FieldRow`、`Chip`、`Dropdown`、`SegmentedControl`、节点标题、pin label 都会继续各自处理长文本，最后又会变成一堆专用 hack。

所以我建议下一轮实现顺序是：

1. `TextOverflow` / `TextAlign` 进入通用 text leaf 或 text props。
2. 新增 `TruncatedText` atom。
3. 让现有 `Label` 可以选择复用这套能力。
4. 给 button/dropdown/list/node label 后续逐步接入。

这样才是补齐通用能力，而不是继续给节点卡片打补丁。
