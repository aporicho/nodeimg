# 模块 contract 模板

> 用于约束 target 文档中各引擎模块的统一写法，确保职责、提供接口、依赖接口、共享模型和验证方式完整闭合。

---

## 上位约束

本模板受 [`architecture-invariants.md`](architecture-invariants.md) 的 **7 条真源**管辖。任何模块设计若与真源冲突，必须先修改真源层文档，不得在本模板或具体模块文档中单方面绕过。

本文档末尾的「**全局设计约束**」是真源 ①（责任边界）和真源 ②（抽象模式）的具体落地项，不是独立决议——它们的权威解释始终在 `architecture-invariants.md`。若未来两份文档出现不一致，以 `architecture-invariants.md` 为准。

---

## 适用范围

本模板适用于引擎内部模块文档，例如：

- 节点图控制器
- 调度器
- 节点管理器
- 缓存管理器
- 产物管理器
- 项目管理器
- 事件系统
- 各类执行器与注册表

## 建议章节顺序

### 1. 文档状态

- `draft`：方向已提出，但接口和边界仍可能变动
- `impl`：职责、接口、共享模型、跨模块契约已收敛，可直接作为实现依据

### 2. 定义

说明模块是什么、解决什么问题，并明确一句话定义。

### 3. 职责边界

至少包含两部分：

- **属于本模块**
- **不属于本模块**

### 4. 提供接口

必须给出：最小接口集、输入/输出、状态修改、事件、副作用。

### 5. 依赖接口

必须列出本模块依赖外部模块的最小方法集，而不是只写“依赖某某模块”。

### 6. 共享模型

列出本模块直接使用的共享模型，并标明权威定义位置。

### 7. 错误与事件

说明模块公共错误类型，以及发布/订阅哪些事件。

### 8. 状态与生命周期

若模块持有长期状态，必须定义空闲、运行中、重置、加载、关闭语义。

### 9. 关键流程

流程图可以保留，但必须建立在接口已经定义的前提上。

### 10. 验证清单

每篇模块文档末尾至少回答：

1. 每条外部箭头是否都有方法名？
2. 是否同时定义了提供接口和依赖接口？
3. 是否引用了唯一权威共享模型？
4. 是否说明了错误、事件、副作用？
5. 是否与 `0.0.1-engine-contract.md`、`0.1.0-models.md` 一致？

## 全局设计约束

以下决议在各模块文档中默认成立：

1. 布局不属于引擎
2. 执行器统一接口
3. 运行时统一写产物
4. 调度器驱动回源
5. 事件统一 `publish(event)`
6. Provider 启动时静态注册
7. `NodeDef` 是唯一权威节点模型
8. `NodeDef = 瘦核心 + 默认化 ExecutionPolicy`
